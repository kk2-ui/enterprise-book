# 系统内多模型企业书与外部 Agent 接口

v1，2026年11月3日。资料由系统集中管理；外部 Agent 通过 HTTP 读取固定资料版本，分批保存自己的完整研究，完成后成为同一家公司下可选择的整本企业书。用户无须下载、解压或转传资料包。

## 用户怎样使用

1. 公司页面 → **创建外部 Agent 任务**。填写实际模型名称、可选精确版本和企业书名称，选择共用资料版本。
2. 将任务窗口中的接入指令交给外部 Agent。Agent 直接读资料、保存章节和研究，可中断后继续；“全部模型版本”页显示任务进度。
3. Agent 提交完成后，刷新页面，在 **企业书版本** 中选择其成稿。全貌、八章、专题、生命周期、长期财务、跟踪、判断、现金估值和研究依据一起切换。

2026年11月4日补齐页面范围：任务的必交部分新增 `life`、`history`、`track`。生命周期解释历史阶段、当前顺逆风和后续变化机制；长期财务保存各期数值及可比口径；跟踪说明基点、观察时点及改变判断的事实，不能编造后续结果。过去已完成的成稿不可覆盖，缺少的页面明确显示本版未保存；协作快照使用自身已保存数据，不能借用当前稿。接口检查只能识别缺页，具体解释是否充分仍由实际研究与阅读判断。

目前服务地址为 `http://127.0.0.1:8778`。Agent 需要能从这台电脑发起 HTTP 请求；纯云端聊天窗口不能直接访问本机地址。系统不自动启动外部模型，也不代管 API 密钥或付费执行。远程访问属于后续部署范围。

已保存的企业书不可覆盖，修订应新建任务和版本。任务中的草稿部分可反复保存。完成意味着所需部分已提交，并不代表事实、估值或写作已获独立认可：新 Agent 成稿统一标为“模型成稿，尚未独立审阅”。模型身份由执行方声明，系统不会认证某家供应商实际执行了研究。

现有格力 `gree-codex-v13` 为历史 Codex 协作稿快照，含八章、八专题、框架 r9、研究 r11 和采用的三项计算。历史精确模型版本及统一信息截止日未登记，不倒填；不能把后建资料版本声称为该稿的唯一输入。原协作稿、旧版和预测记录仍各自保留。

## 数据职责

| 对象 | 保存内容 | 修改方式 |
| --- | --- | --- |
| 共用资料版本 | 确定的原件、全文、披露数据、算术派生、时点和覆盖缺口 | 补采后追加新版本 |
| Agent 任务 | 固定资料版本、模型身份、状态、各部分草稿及进度 | 完成前可续写；完成后锁定 |
| 整本企业书 | 全部正文、专题、判断、假设、计算、引用、缺口和补充来源 | 完成时保存；后续另建版本 |

`source_data/access.py` 提供在线资料访问；`model_books.py` 管理 `book_tasks` 和 `book_editions` 两张表。选中的整本不会读取其他模型的最新专题、现金页或计算。历史协作稿冻结实际采用版本；新 Agent 版只显示该任务写回的正文。共同的原始证据与图片仍可按来源 ID 阅读。

## 每次执行怎样带上标准

本地任务与外部 Agent 共用 `editorial_tasks.py`，直接读取现行 Markdown，不维护另一套摘要标准。外部任务的 `instructions.workflow` 附协调流程全文，`role_instructions` 指向各角色全文：`research` 研究、`writer` 写作或修订、`first_read` 正文首读、`fact_review` 事实机制或投资判断核对、`recheck` 改后复核。每次只读取本次角色所需文件，不将全部角色同时派给一个执行者。标准中的历史示例不是本公司的证据。

2026年11月8日起，角色模板及其开头的实际交付要求放在长篇标准之前，仍由同一文件读取，完整标准保留。执行编写标准v21、编辑流程v12：写作交关键关系的图/表/文字取舍及实际页节，首读独立返回“图示取舍与遗漏”，主编核对具体理由，发布核对已接受的图是否进入对应页面。已有表不自动免除制图，专题有图不抵销主报告缺图。作者的取舍说明归入 `work_map` 或后续核对材料，不能混进首读；缺漏检查不靠图数，也不由接口自动评判质量。

2026年11月6日起采用编写标准v18、编辑流程v9及同步模板。每家公司须讲清重要业务的实际工作、合同角色、收付时间与资金占用；研究交相关条款，首读从正文复述并注明位置，主笔处理全书同类缺陷。要求由上述现行文件直接传给本地与外部模型；已派发的旧指令保留，新任务和中断后接续重新读取生成，不把接口读取成功或模型自报执行当作阅读验收。

同日进一步采用编写标准v19、编辑流程v10：在上述过程要求上，增加整篇核心矛盾、章节推进、主判断与辅助情景的分工及连续阅读验收。研究交有理由的取舍，主笔组织完整文章，首读不预先取得作者主线答案；整篇层次退修后完整回读。五份模板和角色全文同源更新，不新增指令副本或自动质量分数。

本地协调者先在现有研究批次内写本次任务 JSON，再生成可直接派发的 Markdown。例如正文首读：

```json
{
  "role": "first_read",
  "company": "公司名称",
  "question": "本篇讲清的完整经营问题",
  "scope": "本篇全文、相邻前文与实际图片；写明修订版本",
  "output": "同批次内的首读意见文件",
  "end_condition": "先从正文复述交易与资金经过并注明位置；单列图示取舍与遗漏，按实际页面判断现有图及未画出的重要关系；注明未读范围",
  "inputs": {
    "manuscript": ["正文实际路径或URL，明确版本"],
    "figures": ["实际图片路径或URL"],
    "preceding_text": ["读者可见前文实际路径及版本；无前文则用空列表"]
  }
}
```

```bash
python3 scripts/prepare_editorial_task.py research/本批/首读任务.json --output research/本批/首读指令.md
```

`inputs` 还支持 `evidence`（原件和完整研究）、`reviews`（既有意见和处理）、`work_map`（工作地图），按角色选用。生成器拒绝向首读交这三类材料；复核必须同时给实际修订稿和原意见。未看到图像仍记未审，图像URL存在不代表看过。正文、图片、研究材料不复制到新的资料库，只记录实际入口和版本。

外部 Agent 将同样的 JSON 提交到任务接口给出的 `prepare_url`（`POST /api/editorial-instructions/prepare`），取得 `body` 中的完整派发指令。`prepare_example` 提供字段示例，按实际任务填写；本接口只生成文本，不创建研究记录或自动派发代理。它与本地脚本使用同一生成器，也会拒绝将底稿、工作地图和旧意见混入首读。

把生成的完整指令交给执行者，别再只转述几句。`question`和`scope`承接用户与本篇主题要求，说明不可绕开的经营关系；`end_condition`写读者应能回答什么及依据，不能只填“完整、可读、有图”。首读可收到这些中性问题，但不收作者答案、已发现的缺陷或期望结论。其内容是本次派发留档，不回写成第二份现行标准；下一任务重新生成。输出文件不覆盖，旧指令随旧稿保留。外部 Agent 保存实际返回的本次指令；首读只交读者可见内容，不转交整个模型任务对象或作者状态消息。

主编在原批次记录里接收实际成果：阅读意见须说明理解、公司信息增量、图文取舍及未覆盖范围，经济意见须说明事实、假设与结论支持程度；修订后回读受影响完整稿。程序只检查指令材料和接口行为，不评定文章好坏；`complete` 仍只形成 `not_reviewed` 的模型成稿，不能因生成了指令或自报遵守流程升级为已审妥。用户没有认可的旧稿也不自动成为合格范文。

只返回“已有计算表，无需重复图”不足以接收：主编须确认是否真的比较了表达效果，哪种关系已经讲清、哪些仍靠读者拼接。完整复算和直观理解各自保留，不能互相替代；未解决的重要图文问题按原任务修订，不让用户承担发现遗漏的工作。实际图片已审但插错页或没有插入，发布检查仍须处理。

## HTTP 约定

以下路径均相对于服务地址。`cid` 为公司 ID，格力是 `8478678d80434d8e`；目前共用资料版本为 `gree-sources-20261102-v1`。所有写请求使用 `Content-Type: application/json`。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/companies/{cid}/data/versions` | 共用资料版本列表 |
| `GET /api/companies/{cid}/data/versions/{version}` | 固定目录、缺口、资料修订和各阅读链接 |
| `GET .../data/versions/{version}/documents/{doc}?start_page=1&end_page=10` | 全文按 PDF 页序读取；1 起始，单次最多 50 页 |
| `GET .../data/versions/{version}/documents/{doc}/original` | 固定的原始文件 |
| `GET .../data/versions/{version}/search?q=返利&document=ar2025` | 全文词面检索；document 可省略，最多返回 30 个匹配页 |
| `GET .../data/versions/{version}/facts?document=ar2025` | 披露值、派生值与数据字典；document 只筛选披露值 |
| `POST /api/companies/{cid}/book-tasks` | 创建任务 |
| `GET /api/companies/{cid}/book-tasks` | 任务及进度 |
| `GET /api/companies/{cid}/book-tasks/{task}` | 恢复任务，包括已保存全文 |
| `GET /api/companies/{cid}/book-tasks/{task}/instructions` | 可直接交给 Agent 的任务、读写接口和示例 |
| `GET /api/editorial-instructions/{role}` | 对应角色的当前标准与任务模板全文；不包含任何公司稿件、自评或旧意见 |
| `POST /api/editorial-instructions/prepare` | 由具体范围与输入生成含当前标准的完整指令；返回body，不写数据库 |
| `POST .../book-tasks/{task}/status` | waiting / running / failed，以及执行说明 |
| `POST .../book-tasks/{task}/parts/{part_id}` | 保存一个完整部分 |
| `POST .../book-tasks/{task}/complete` | 创建不可覆盖整本；重试返回同一本 |
| `GET /api/companies/{cid}/books` | 已完成企业书列表 |
| `GET /api/companies/{cid}/books/{edition}` | 本版全部正文及元数据 |

创建任务请求：

```json
{
  "title": "格力 · 某模型独立研究",
  "model": {"name": "实际模型名称", "version": "实际精确版本或空字符串"},
  "source_version": "gree-sources-20261102-v1"
}
```

接入后先读 `instructions.workflow` 的完整流程，再在研究、写作或审阅任务开始时读对应 `role_instructions` 全文；按上文生成和保存具体派发指令。接口摘要不能替代标准。读取资料目录后提交状态：

```json
{"status":"running","message":"正在研究公司全貌与现金来源"}
```

保存正文示例，提交到 `.../parts/chapter-1`：

```json
{"title":"企业沿革与业务边界","body":"完整 Markdown 正文。关键事实 [[doc:ar2025@24|2025年收入构成]]。"}
```

必需部分为 `overview`、`chapter-1` 至 `chapter-8`、`judgment`、`valuation`、`assumptions`、`calculations`、`references`、`gaps`。章节目录只是承载结构，不要求一次任务写完。另设专题用 `topic-自定义ID`。各部分均包含非空 `title` 和完整 Markdown `body`，`calculations` 应给出可复算输入、算式、单位及权益口径；系统不会替模型生成参数。

引用 `[[doc:资料ID@页序|名称]]` 会定位本任务固定版本原文，并在保存时核对资料和页序。图片沿用 `[[figure:来源ID|图注]]`，需先通过已有资料上传功能登记。补充资料在完成时逐项说明，不能把不同信息集的结果称为完全相同输入实验。

完成请求：

```json
{
  "model":{"name":"实际模型名称","version":"实际精确版本"},
  "additional_sources":[{"title":"另行补充的公告","url":"公告原文地址"}]
}
```

没有补充来源时使用空数组。已明确的模型名称/版本与执行结果不符时应新建对应任务；未知版本可由执行者完成时回填。保存失败应读取返回的 `error`，补齐缺失部分或修正来源页序后继续；不要用占位段落冒充完整研究。

## 研究与阅读边界

### 企业全景

模型版共用[企业全景页](WRITING_STANDARD.md#共同的企业全景页)。保存 `overview` 时，`title` 和 `body` 保存本公司经营释读，`display` 保存该版主体、实绩及趋势的结构化资料。字段沿用企业书档案的 `identity`、`metrics`、`series` 和 `overview`，另有封面的 `subtitle`、`intro` 与 `cover_period_text`。各年数据具有 `year`、`period`（例如 FY2025）、`kind`（annual）及按指标键记录的 `values`。各项数值含 `value`（金额以人民币百万元计）、原表 `raw`、`raw_unit`、`document`、`page`、`column` 和 `quote`。原件及页码归属该书固定资料版。完整示例见[中国石油和三一接入](research/petrochina_overview_revision/publish.py)。未提供结构化资料的历史版本仍可阅读，在相应全景位置显示其数据覆盖。历史回演可标记 `historical: true` 以沿用当时的信息截止日。

独立研究从固定资料和缺口开始，不先读取另一模型结论。两线研究、单一主笔顺序写作、完整问题拆分、资产→EPV→增长分别研究，以及独立审阅规则继续执行。系统检查必需部分存在及引用位置，不自动判断事实准确、全貌充分或估值可靠。

本次提供逐本阅读和版本切换；尚无自动调度模型、自动审阅、差异归因面板或模型排名。比较时先看事实、资料范围、正常化假设、资本用途及推理，不用模型多数票决定公司价值。

实现与验证见[本批记录](research/model_books_20261102/架构与实施.md)。

所有模型的估值主报告还须执行[可独立复算要求](WRITING_STANDARD.md#主线清楚不等于把正文缩成摘要)：系统正文完整展开关键取值、计算及经济含义，不以结果摘要和专题跳转替代；首读须实际复算，经济审阅核源，仍通过现有同源角色指令接入。
